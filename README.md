# lasik palette

The colors behind the Lasik themes for [VS Code](https://github.com/LasikTheme/vscode), [Konsole](https://github.com/LasikTheme/konsole), [Kitty](https://github.com/LasikTheme/kitty) and [Claude Code](https://github.com/LasikTheme/claude-code). Lasik is a dark theme made for sensitive eyes: comfortable for reading a lot of text, with good contrast.

![The Lasik scale: every hue in steps 50 to 950 with hex values and contrast ratios](./screenshots/palette.svg)

All colors are in [`palette.toml`](./palette.toml). Each hue comes as a **scale**, from step **50** (lightest) to **950** (darkest), like Tailwind's colors. Each step is a contrast against the background, `OBSIDIAN` `#01030a`, so the step number says what a color can be used for:

| Step | Contrast on OBSIDIAN | Use it for |
|---|---|---|
| 50 | 17.5:1 | |
| 100 | 16:1 | |
| 200 | 14.5:1 | bright text, headings |
| 300 | 12.5:1 | |
| 400 | 10:1 | text |
| 500 | 7:1 | High Contrast text: **500 and lighter** is WCAG AAA |
| 600 | 4.5:1 | dimmed text: **600 and lighter** is WCAG AA |
| 700 | 3:1 | borders and UI lines (3:1 is the minimum to see an edge) |
| 800 | 2:1 | backgrounds: **800 and darker** |
| 900 | 1.5:1 | hover and selection backgrounds |
| 950 | 1.25:1 | faint tints: line highlights, whole diff lines |

- **NEUTRAL** is the text, surfaces and lines: the hand-picked periwinkle `#a8bcfc` (NEUTRAL_400), a blue that's very easy to read on OBSIDIAN. The other 13 hues are for syntax colors, terminal colors and accents.
- **The backgrounds** are `OBSIDIAN` and `OBSIDIAN_DEEP` (`#000105`, the Lasik Dark High Contrast background).
- Each program names its color slots differently (Konsole "Intense", VS Code "ansiBright", Alacritty "bright"), so each theme decides which step goes where.
- Changes are listed in [CHANGELOG.md](./CHANGELOG.md).

## The scale

The scale is generated by [`scripts/scale.ts`](./scripts/scale.ts) and stored in `palette.toml`. Run it again after changing a hand-picked color:

```sh
deno run --allow-read --allow-write scripts/scale.ts
```

- **Hand-picked colors stay exactly as they are.** Each hue's base color (RED `#d24e6d`, PEACH `#d98677`, …) sits at the step nearest to its contrast, for example PEACH at 500 (7.5:1) and APRICOT at 300 (13:1). It's marked "hand-picked" in `palette.toml` and with ★ in the image.
- **The other steps only change lightness**, in OKLCH (see "Two color models" below), so the hue stays the same. Each step's lightness is found so its contrast on OBSIDIAN is the step's target.
- **Lighter than the base color, the chroma stays the same.** When a light color is too colorful for a normal screen, its chroma is lowered until it fits, which is why steps 50–100 are nearly white.
- **Darker than the base color, the chroma shrinks with the lightness** (`C × L / L_base`), like mixing the color into the background. Dark steps used as backgrounds stay calm instead of turning into deep, saturated colors.
- **NEUTRAL is made from PERIWINKLE**, like the other hues from their base color: `#a8bcfc` stays exactly at step 400, and the other steps are generated from it. The old SLATE, PERIWINKLE, LAVENDER and SILVER families are NEUTRAL steps now.
- **One scale for every hue, no extra steps.** If a theme needs a color between two steps, it uses one of the two steps.

### What the scale replaced

Before the scale, each color had up to five named tiers (`NAME_MUTED`, `NAME`, `NAME_DEEP`, `NAME_BRIGHT`, `NAME_QUIET`). The names didn't say where a color sat: DEEP was a different step for every hue, and MUTED often had the same lightness as the base color. SLATE, PERIWINKLE, LAVENDER and SILVER were separate families; they're now NEUTRAL steps.

The old tiers are still in `palette.toml`, in the "legacy tiers" section, but no theme uses them any more: every port moved to the scale on 2026-10-25. The hand-picked base colors in that section are what `scripts/scale.ts` builds the scale from, and the VS Code build reads the rest to translate old colors in its source into scale steps.

## How the legacy tiers were made

Most colors were picked by hand. The rest were calculated from the base color with the formulas below, then **stored** in `palette.toml` (they're not recalculated when you change a base color).

### Two color models

- **OKLCH** for lightness and colorfulness. It describes a color with three numbers that match how people see it:
  - **L**: lightness, from 0 (black) to 1 (white)
  - **C**: chroma, how colorful it is (0 = gray)
  - **H**: hue, the color angle in degrees (red ≈ 10°, yellow ≈ 90°, blue ≈ 245°)

  Changing L in OKLCH makes a color look lighter or darker without its hue drifting. That doesn't work in RGB or HSL. ([OKLab by Björn Ottosson](https://bottosson.github.io/posts/oklab/), the base of OKLCH.)
- **sRGB** (normal hex colors) for mixing with the background, because that's how a screen blends a see-through color.

When a calculated color is too colorful for a normal screen (outside sRGB), its chroma is lowered in small steps (0.002) until it fits. Hue and lightness stay the same.

### Formulas

| Tier | How it's made | Hand-picked range | Formula for new colors |
|---|---|---|---|
| **MUTED** | same lightness, less colorful | chroma 0.27× (GREEN) to 0.69× (BLUE) | `L` same, `C × 0.564`, `H` same |
| **DEEP** | darker and more colorful | 8 colors: `L` −0.04 to −0.08, chroma 1.05× to 1.49× | `L − 0.076`, `C × 1.31`, `H` same |
| **BRIGHT** | lighter | none (all calculated) | `L + 0.08` (at most 0.97), `C` same, `H` same |
| **QUIET** | mixed into the background | none (all calculated) | for each of R, G, B: `0.35 × color + 0.65 × OBSIDIAN` |

- **The numbers come from the hand-picked colors.** 0.564 is the median chroma ratio of 11 hand-picked muted colors (SLATE is left out: its muted color was made lighter in May 2026, not less colorful). −0.076 and 1.31 are the medians of the 8 hand-picked deep colors that are darker *and* more colorful (RED, PEACH, TUMBLEWEED, YELLOW, GREEN, BLUE, MAUVE, PINK). TEAL, SAPPHIRE and SLATE deep are darker but less colorful, so they were left out of the median.
- **QUIET's 35%** is the opacity the VS Code theme already used for dimmed JSON quotes. Mixing into the background (instead of making the color see-through) gives one solid color that looks the same everywhere.
- **Contrast** is the WCAG 2 formula: `(L1 + 0.05) / (L2 + 0.05)`, where L1 and L2 are the relative luminance of the lighter and the darker color. It goes from 1:1 to 21:1.

### Hand-picked or calculated

| Tier | Hand-picked | Calculated |
|---|---|---|
| Base | all 17 (APRICOT, ROSE, SKY, PERIWINKLE and SILVER came from the old VS Code theme) | none |
| MUTED | the 12 original colors | APRICOT, ROSE, SKY, PERIWINKLE. SILVER has none: it's a gray, so there is no color to take away |
| DEEP | the 11 original colors except LAVENDER | LAVENDER, APRICOT, ROSE, SKY, PERIWINKLE, SILVER |
| BRIGHT | LAVENDER (`#e4edfd`, its original intense color, moved to OBSIDIAN's hue) | all others |
| QUIET | none | all except SLATE |

### Exceptions

- **`YELLOW_BRIGHT`** uses `L + 0.02` and `C × 1.1` instead of `L + 0.08`, because yellow is already very light: +0.08 would make it almost white.
- **The LAVENDER family has OBSIDIAN's hue (261°).** Each lavender kept its lightness and chroma, and only its hue moved from about 273° to the background's, so the text and the background are the same blue (2026-10-24). LAVENDER_QUIET is the 35% mix of the new LAVENDER.
- **`LAVENDER_BRIGHT`** keeps the hand-picked `#e8ecfd`'s lightness and chroma (now `#e4edfd` at OBSIDIAN's hue). Lavender is the terminal text color, and anything lighter gets close to pure white, which causes a halo around letters on a dark background.
- **`SLATE_BRIGHT`** is `SLATE_MUTED` made lighter (only `L` goes up) until it reaches 5.0:1. Bright black is used for shell suggestions and git hints, so it has to be readable.
- **`OBSIDIAN_DEEP`** is `#000105`: OBSIDIAN with R, G and B halved, so it's darker with the same blue hue (257° against 261° in OKLCH). It's the Lasik Dark High Contrast background, as close to black as OBSIDIAN gets (1.007:1 against `#000000`). Darker steps lose the tint.
- **`SLATE_QUIET`** is `#2a324b` (the hand-picked dark slate) instead of the 35% mix, which would be `#161b2c` (1.2:1), too close to the background to see.

## Known gaps

Colors the themes need but the palette doesn't have yet. Until they're added, the themes use the closest palette color or the program's own default.

- **Faint background tints, fainter than QUIET:** filled by the scale's steps 900 and 950. The themes don't use them yet (Claude Code still uses its own diff line colors).

## Update the image

The image is generated from `palette.toml`, so it always matches the palette. After changing a color (and running `scripts/scale.ts`), run this from the repo root:

```sh
deno run --allow-read --allow-write scripts/render-palette.ts
```
